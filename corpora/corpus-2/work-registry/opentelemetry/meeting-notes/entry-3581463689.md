## Discussions

### 1. Next Go release & OTelConf RC support

- Release blocked on RC support module; PR needs reviews.
- Requested changes from Alex do not need to be in the current PR.
- Module is `0.x`; breaking changes acceptable later.
- Avoid exposing public API known to be removed immediately.
- Discussed handling experimental features:
  - `WithExperimentalFeatures`-style flag likely unhelpful.
  - Possible `x` submodule to clearly isolate experimental APIs.
  - Aligns with OTel-wide push for opt-in experimental features.

### 2. HTTP default client deprecation (OTel HTTP)

- Work deprecating default HTTP client usage is in progress.
- `POST`/`GET` helpers rely on `http.DefaultClient` and limit configurability.
- Follow-up PRs exist; need review for inclusion in upcoming release.

### 3. Observability work & non-blocking PRs

- Several observability PRs (e.g., self-observability for OTel gRPC) are ongoing, not release-blocking.
- Two non-observability items noted:
  - Sync map / atomics for fixed bucket histograms.
  - Exemplar reservoir changes.
- Safe to slip to next release; include if ready.

### 4. Stabilizing new attribute value types

- Discussion about stabilizing new spec attribute types (byte arrays, “any” type).
- Prototype implementation exists and needs review.
- Considered tricky; careful review needed around limits and types.

### 5. Processor `Enabled` method

- Proposal from Robert to move `Enabled` from filter processor to main processor interface.
- Spec now stabilized and allows this.
- Pros: consistent API, less ad-hoc type assertion/boilerplate in docs.
- Con: processors that are “always enabled” need a trivial `Enabled() bool { return true }`.
- General agreement; will revisit for final confirmation.

### 6. OTLP `insecure` support (logs, env vars, spec)

- PR adds `insecure` (env var) support for OTLP **logs**, matching traces/metrics.
- HTTP OTLP config historically messy; env vars common in practice.
- Spec unclear due to moratorium on env vars.
- Direction: add logs support in Go; push for spec clarity later.

### 7. Collector protobuf changes & PDataGen

- Collector removed dependency on Go protobuf types; now uses `pdataGen`.
- Large internal rewrite; significant line count reduction.
- Benchmarks improved (fewer allocations).
- Some cross-language quirks surfaced but manageable.
- Go SIG interested in exploring similar approaches; needs more benchmarking.

### 8. KubeCon & talks

- First SIG meeting since KubeCon.
- Members encouraged to share notable talks and videos once available.

## Decisions

- Merge OTelConf RC support PR as-is (pending normal review).
- Track experimental API structure review (e.g., `x` submodule) under the `1.40.0` milestone.
- Add OTLP `insecure` support for logs to align with traces/metrics.
- Continue supporting env-var config despite lack of formal spec guarantees.
