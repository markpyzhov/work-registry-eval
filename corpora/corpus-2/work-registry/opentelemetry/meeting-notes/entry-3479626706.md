### Adding env var support for OTEL_EXPERIMENTAL_CONFIG_FILE

Reference: Adding env var support for OTEL_EXPERIMENTAL_CONFIG_FILE: https://github.com/open-telemetry/opentelemetry-go-contrib/issues/8059

- Goal:
  - If the env var is present, load the indicated config file and configure the SDK automatically, minimizing user code.
- Current ecosystem notes:
  - PHP reports support; other languages vary (JS likely working on it; C++ explicitly not supporting).
  - Go users are accustomed to programmatic setup; unclear if SDK-level support is necessary.
- Go implementation options discussed:
  - SDK experimental feature-flag approach:
    - Use internal “x”/experimental packages to expose a feature gate for the env var.
    - Check the env var during SDK setup (e.g., TracerProvider construction), and if enabled, configure from the file.
    - Complications:
      - Potential import cycles (e.g., if otelconf needs sdk and vice versa).
      - Decision required on how to handle passed options vs. config file (ignore vs. merge).
      - Requires similar work across trace, metrics, and logs modules.
  - Contrib-first approach (preferred short term):
    - Implement in opentelemetry-go-contrib/otelconf:
      - Provide an explicit function to load from OTEL_EXPERIMENTAL_CONFIG_FILE and construct/return SDK providers.
      - Optionally offer an init-based side effect that sets the global provider if the env var is set (not ideal, but acceptable during experimental phase to collect feedback).
    - Advantages:
      - Avoids SDK import cycles and keeps experimental behavior isolated.
      - Lets users opt in; easier to iterate and gather feedback before considering SDK-level integration.
- Global vs. explicit provider setup:
  - The otel global package has its own subtleties; supporting both code paths may be necessary.
  - Global setup increases risk of cycles/complexity; explicit function in contrib is cleaner initially.
- Tentative direction:
  - Do not add SDK-level support in the short term.
  - Prototype in contrib (otelconf); gather user feedback.
  - Revisit SDK inclusion later if demand and design stabilize.
